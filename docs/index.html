v1.0.0 Production Release • Windows & Linux Desktop

The Standalone Desktop Hub for Universal Cloud Sync.

unicSync is a native desktop application for Windows and Linux that turns any local folder on your computer into an Infinite Cloud Drive. Powered by the crash-resilient Rust `uSync` background engine, unicSync delivers storage tiering, multi-cloud destination wizards, and zero-knowledge encrypted offload to AWS S3, Google Drive, or WebDAV.

What is unicSync?

A standalone desktop architecture built for privacy, performance, and crash immunity.

Standalone Desktop App

Native application for Windows and Linux with an identical UI look and feel, dark slate aesthetic, and consistent user flows across platforms.

Rust Engine Core

Bundles the compiled Rust `sync-agent` daemon (PE32+ on Windows, ELF on Linux) for 5 MB chunk streaming, atomic SQLite WAL persistence, and crash recovery.

Universal Cloud Freedom

Supports any cloud destination (AWS S3, Cloudflare R2, MinIO, Nextcloud WebDAV, Google Drive) with zero vendor lock-in.

Quickstart Walkthrough

Get up and running on Linux or Windows in under three minutes.

1

Build Release Binaries

Run the release build in the `uSync` engine workspace. The Makefile compiles both the Linux (`sync-agent`) and Windows (`sync-agent.exe`) binaries and automatically copies them into `unicSync/assets/bin/`:

# Inside rSync directory:
make build-release

# Generated release binaries:
target/release/sync-agent (Linux ELF, ~5.2 MB)
target/x86_64-pc-windows-gnu/release/sync-agent.exe (Windows PE32+, ~4.5 MB)
2

First-Time Setup (Onboarding Wizard)

On launch, unicSync guides you to select a local folder on your computer to watch and sync:

  • Default Linux path: /home/user/CloudDrive
  • Default Windows path: C:\Users\username\CloudDrive
  • Click Browse to select any existing local folder on your PC.
  • Click Initialize & Launch Engine. The app automatically spawns the background daemon and begins monitoring the folder.
3

Connect Cloud Storage Destination

Open Profiles from the navigation rail, click Add Profile, and enter your AWS S3 bucket credentials or Nextcloud WebDAV credentials. Any file placed into your watch directory will automatically stream to the cloud!

4-Worker Parallel Chunk Pool

`uSync` operates a bounded 4-worker upload queue. When large video files (1 GB+) are uploaded, the file is split into 5 MB chunks, and the 4 workers process parts in parallel. If network drops occur, only the interrupted 5 MB chunk is retried.

2. Storage Tiering (LRU Cache Manager)

Virtualize 1 TB+ of cloud storage without exhausting your PC's local disk.

The Files tab provides an intuitive browser with status badges inspired by OneDrive and iCloud, but fully open-source and universal across any cloud provider:

💾 Local (Buffering)

Newly written file on local PC disk. The payload resides locally and is actively queued for cloud offload.

✅ Synced (Cached)

File is safely stored in the cloud and cached locally on your PC for instant zero-latency access.

☁️ Cloud Only (Dataless Stub)

The local payload was safely evicted from disk to free up PC drive space. The file name and metadata remain visible; clicking hydrate downloads it on-demand.

Tiering Control Actions

Free Up Space (Evict): Clears local physical bytes from disk while preserving the cloud backup and keeping a dataless stub on disk.
Download to Device (Hydrate): Fetches the payload from your S3 or WebDAV bucket and restores it as a cached local file.
Discover Cloud Files (Import): Scans your remote bucket for files uploaded from other computers and indexes them without downloading full payloads.
Restore All: Batch downloads all remote cloud objects back to the local computer disk.

3. Multi-Cloud Destination Wizard

Connect to any cloud storage target without editing config files.

Configure, manage, and toggle between cloud providers directly from the UI:

AWS S3 / MinIO / R2

Custom endpoint URLs, SigV4 authentication, bucket name, access key, secret key, and optional bucket subfolder prefix.

WebDAV / Nextcloud

Nextcloud, ownCloud, or custom WebDAV URLs with standard HTTP Basic Auth or App Passwords.

Google Drive

OAuth2 Bearer tokens and target Parent Folder ID utilizing Google Drive v3 Resumable Upload protocol.

Mock Sandbox

In-memory and local mock backend for sandbox verification, offline resilience testing, and QA.

4. Zero-Knowledge Encryption & PIN Protection

Enterprise-grade cryptographic hardening built right into the app.

Client-Side AES-256-GCM Encryption

When enabled, every 5 MB chunk is encrypted in RAM prior to network transmission using authenticated AES-256-GCM with keys derived via PBKDF2-HMAC-SHA256. Cloud providers only see opaque ciphertext.

App PIN & Brute-Force Lockout

Protect your dashboard and files from unauthorized local access. Configure a 4-to-8 digit PIN. After 5 consecutive invalid attempts, the dashboard enters an exponential security lockout.

5. Deletion Policies Explained

Choose how local file deletions are handled in the cloud.

Policy Mode Local Action Cloud Action Best Use Case
Safe Archive (keep_cloud) File deleted locally Remote cloud file is KEPT Default. Free up PC drive space without losing cloud backups.
Strict Mirror (remove_both) File deleted locally Remote cloud file is DELETED Strict 1:1 two-way directory synchronization.
Local Only (untrack) Untracked locally Cloud state left intact Temporary disconnect of specific files or folders.

6. Real-Time Streaming Logs

Full transparency into engine operations, network reconnects, and chunk uploads.

The Logs tab streams live traces directly from the Rust `sync-agent` background process:

  • Level Filtering: Toggle between ALL, INFO, WARN, ERROR, and DEBUG.
  • ANSI Clean: Strips console color escapes for crystal-clear readability.
  • Process Diagnostics: Displays the active process PID, web port (e.g. 8484), and log file location.

7. Seamless Windows & Linux Desktop Experience

Built for background operation on modern workstations.

unicSync is optimized for daily desktop usage:

  • Background Persistence: The Rust daemon continues running in detached mode even when the window is closed.
  • Cross-Platform Parity: Identical dark slate theme, shortcuts, and window dimensions (1280x720) across both Ubuntu/Debian/Arch Linux and Windows 10/11.
  • Zero Resource Bloat: Lightweight Flutter frontend consuming minimal RAM, backed by a native Rust daemon optimized with fat LTO and memory-bounded streaming.

Frequently Asked Questions & Troubleshooting

Common answers and operational best practices.

What happens if the app window is closed while a transfer is in progress?

Nothing stops! The Flutter UI is a presentation layer. The Rust `sync-agent` runs as a detached background daemon on localhost. Your upload will continue uninterrupted in the background. Reopening unicSync immediately reconnects to the live daemon.

What happens if power is cut or the computer restarts mid-upload?

The engine is 100% crash-resilient. Every chunk completion is atomically committed to SQLite in WAL mode. Upon relaunching, the engine verifies existing cloud chunks and resumes from the exact byte boundary—never restarting from 0.

Where are the local database and log files stored?
Linux: ~/.local/share/com.rsync.unic_sync/
Windows: %APPDATA%\com.rsync.unic_sync\
How do I restart or stop the background engine?

Go to the Settings screen in the app and click the Stop Engine or Restart Engine buttons. You can also change the watched folder directly from Settings.
