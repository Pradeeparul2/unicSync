Cross-Platform Flutter Companion for rSync

The Autonomous Control Hub for Infinite Cloud Storage.

unicSync transforms standard USB flash drives, dashcam SD cards, and desktop folders into an Infinite Cloud Drive. Powered by the crash-resilient Rust `sync-agent` engine, unicSync delivers real-time bandwidth meters, multi-cloud destination wizards, and zero-knowledge encrypted offload to AWS S3, Google Drive, or WebDAV.

What is unicSync?

Understanding the companion architecture and why it exists.

The Edge Problem

Edge devices (dashcams, thumb drives, creator cameras) suffer from severe flash capacity limits, sudden power cuts, and network disconnects that corrupt traditional file uploads.

The Rust Engine

`rSync` (`sync-agent`) runs quietly in the background, chunking files into bounded 5 MB blocks, calculating SHA-256 hashes, and persisting progress in atomic SQLite WAL transactions.

The Flutter Companion

unicSync provides the unified presentation and control interface on Linux, Windows, macOS, Android, and iOS. Zero business logic duplication—pure visual clarity.

Quickstart Walkthrough

Get up and running in under three minutes.

1

Build or Launch unicSync

Ensure you have built the companion binaries via the root `Makefile` in `rSync`, then launch unicSync:

# In rSync directory (generates Linux & Windows release daemons):
make build-release

# In unicSync directory:
flutter run -d linux # For Linux desktop
flutter run -d windows # For Windows desktop
2

First-Time Setup (Onboarding Wizard)

When you launch unicSync for the first time, the onboarding screen guides you to choose a target watch directory:

  • Default Linux suggested path: /home/user/CloudDrive
  • Default Windows suggested path: C:\Users\username\CloudDrive
  • Click Browse to select any USB drive or external folder.
  • Click Initialize & Launch Engine. The app automatically spawns the background daemon and mounts the directory.
3

Add Cloud Destination & Sync

Navigate to Profiles on the left navigation rail. Click Add Profile and enter your AWS S3 bucket credentials or Nextcloud WebDAV credentials. Any file placed into your watch directory will automatically stream to the cloud!

Worker Pool Breakdown

`rSync` operates a 4-worker upload queue. When large video files (1 GB+) are uploaded, the file is split into 5 MB chunks, and the 4 workers process parts in parallel. If network drops occur, only the interrupted 5 MB chunk is retried.

2. Infinite Storage Tiering (LRU Cache Manager)

Virtualize 1 TB+ of cloud storage on an 8 GB or 32 GB local drive.

The Files tab provides an intuitive browser with status badges inspired by OneDrive and iCloud, but fully open-source and universal across any cloud provider:

💾 Local (Buffering)

Newly recorded or written file on disk. The payload resides in physical flash and is actively queued for cloud offload.

✅ Synced (Cached)

File is safely stored in the cloud and also cached locally in physical storage for instant zero-latency access.

☁️ Cloud Only (Dataless Stub)

The local payload was safely evicted from disk to free up physical space. The file name and metadata remain visible; clicking hydrate downloads it on-demand.

Tiering Control Actions

Free Up Space (Evict): Clears the local physical bytes while preserving the cloud backup and keeping a dataless stub on disk.
Download to Device (Hydrate): Fetches the payload from your S3 or WebDAV bucket and restores it as a cached local file.
Discover Cloud Files (Import): Scans your remote bucket for files uploaded from other computers or devices and indexes them without downloading full payloads.
Restore All: Batch downloads all remote cloud objects back to the physical local drive.

3. Multi-Cloud Destination Wizard

Plug-and-play storage backends with no proprietary cloud lock-in.

Configure, manage, and toggle between cloud providers directly from the UI without manually formatting config files:

AWS S3 / MinIO / R2

Custom endpoint URLs, SigV4 authentication, bucket name, access key, secret key, and optional bucket subfolder prefix.

WebDAV / Nextcloud

Nextcloud, ownCloud, or custom WebDAV URLs with standard HTTP Basic Auth or App Passwords.

Google Drive

OAuth2 Bearer tokens and target Parent Folder ID utilizing Google Drive v3 Resumable Upload protocol.

Mock Sandbox

In-memory and local mock backend for sandbox verification, offline resilience testing, and QA.

4. Zero-Knowledge Encryption & PIN Protection

Enterprise-grade cryptographic hardening built right into the companion.

Client-Side AES-256-GCM Encryption

When enabled, every 5 MB chunk is encrypted in RAM prior to network transmission using authenticated AES-256-GCM with keys derived via PBKDF2-HMAC-SHA256. Cloud providers only see opaque ciphertext.

Device PIN & Brute-Force Lockout

Protect your dashboard and files from unauthorized local access. Configure a 4-to-8 digit PIN. After 5 consecutive invalid attempts, the dashboard enters an exponential security lockout.

5. Deletion Policies Explained

Choose how local file deletions are handled in the cloud.

Policy Mode Local Action Cloud Action Best Use Case
Safe Archive (keep_cloud) File deleted locally Remote cloud file is KEPT Default. Dashcam footage & photos offload to free local space.
Strict Mirror (remove_both) File deleted locally Remote cloud file is DELETED Strict 1:1 two-way directory synchronization.
Local Only (untrack) Untracked locally Cloud state left intact Temporary disconnect of specific files or folders.

6. Real-Time Streaming Logs

Full transparency into engine operations, network reconnects, and chunk uploads.

The Logs tab streams live traces directly from the Rust `sync-agent` background process. Features include:

  • Level Filtering: Toggle between ALL, INFO, WARN, ERROR, and DEBUG.
  • ANSI Clean: Strips console color escapes for crystal-clear readability.
  • Process Diagnostics: Displays the active process PID, web port (e.g. 8484), and log file location.

7. Autonomous USB-C Smart Drive Integration

Pair seamlessly with standalone hardware dongles.

When the physical `rSync` companion hardware (Rockchip RV1103 / RV1106 powered USB-C drive) is plugged into your PC or mobile phone, unicSync automatically senses the CDC-NCM reverse-tethered network interface at 192.168.7.2:8080.

You can seamlessly toggle the active target in the top-right engine switcher between 💻 Local PC Drive and 💾 USB-C Smart Drive.

Frequently Asked Questions & Troubleshooting

Common answers and operational best practices.

What happens if the app is closed while a transfer is in progress?

Nothing stops! The Flutter UI is just a presentation layer. The Rust `sync-agent` runs as a detached background daemon. Your upload will continue uninterrupted in the background. Reopening unicSync immediately reconnects to the live daemon.

What happens if power is cut or the USB drive is unplugged mid-upload?

The engine is 100% crash-resilient. Every chunk completion is atomically committed to SQLite in WAL mode. Upon reconnection or power restoration, the engine verifies existing cloud chunks and resumes from the exact byte boundary—never restarting from 0.

Where are the local database and log files stored?
Linux: ~/.local/share/com.rsync.unic_sync/
Windows: %APPDATA%\com.rsync.unic_sync\
macOS: ~/Library/Application Support/com.rsync.unic_sync/
How do I restart or stop the background engine?

Go to the Settings screen in the app and click the Stop Engine or Restart Engine buttons. You can also change the watched folder directly from Settings.
